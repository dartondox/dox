    Changelog

    What changed in each package, newest first. This page is made from the CHANGELOG.md files in the repo when the docs are built.

    dox_annotation

    3.2.0

    • New: package:dox_annotation/install.dart with Installer, the steps of a <package>:install command that dox add runs. writeFile (only when the file is not there), makeFolder, addEnv (to .env and .env.example, only when the key is missing), addEnvGetter (to AppEnv in lib/config/env.dart), addDependency (dart pub add, also dev), buildRunner, note (add your own summary line) and printSummary. lines is read only. Every step is safe to run twice. It is not in the dox_annotation.dart barrel.
    • New: DoxProvider.boot(). It runs once in every isolate after setup() of every provider is done. Optional, the default does nothing. dox_queue starts its in-process worker there, so the other providers (eg. the mail jobs) are ready first.
    • New: package:dox_annotation/provider.dart with DoxProvider. It moved here from dox_core, so a package below dox_core can have a provider. It is not in the dox_annotation.dart barrel.
    • New: package:dox_annotation/command.dart with Command and MigrationFile. They moved here from dox_core, so a package below dox_core can add dox commands.
    • New: GlobalMiddleware, a small shared list that packages use to add global middleware at startup. A package that does not depend on dox_core can use it. GlobalMiddleware.clear() is for tests.

    dox_builder

    3.2.1

    • New: a default that reads the global env (like env.appEnv) stopped the app with a stack overflow. Now load() throws a clear StateError that says to use the getter directly.
    • Fix: a run of capitals in an env getter name is one word now. dbURL read DB_U_R_L, now it reads DB_URL. Also jwtTTL => JWT_TTL and httpURLPath => HTTP_URL_PATH. Names like s3Bucket and oauth2ClientId do not change. If your .env has a key like DB_U_R_L, rename it, or use @EnvKey('DB_U_R_L').
    • Fix: @EnvKey through a const variable (const k = EnvKey('X'); then @k) was ignored. Now it is read.
    • Fix: an env getter named r or reader made env.g.dart fail to compile. The generated load() now uses $r and $reader.
    • Fix: an instance field in a @DoxEnv() class was not read from the env, with no warning. Now it is a build error that says to use a getter.
    • Fix: in a @DoxEnv() class, a getter body that uses another getter saw the default of that getter, not the loaded value. So String get appUrl => 'http://localhost:$appPort'; gave port 3000 even with APP_PORT=4000. Now a getter body runs on the loaded env and sees the real values. A key that is set still wins over the body. A default that throws still stops the app in load(). Run dart run build_runner build to get the new env.g.dart.

    3.2.0

    • New: the job builder moved here from dox_queue. It writes lib/generated/jobs.g.dart with every @Job() class, the same file as before. It runs only in an app that has dox_queue in dependencies or dev_dependencies. (When the build can not read the app's pubspec.yaml, it runs when the app can import dox_queue.) If your build.yaml names the builder dox_queue:jobs, change it to dox_builder:jobs.
    • Breaking: this dox_builder needs dox_queue 3.2 or newer. With dox_queue 3.1, both packages have a builder for jobs.g.dart, and build_runner stops at start with "outputs collide". Run dart pub upgrade to move both together. An app that must stay on dox_queue 3.1 turns off the new builder, and the dox_queue 3.1 builder keeps making the file: 
      # build.yaml of the app
targets:
  $default:
    builders:
      dox_builder:jobs:
        enabled: false
    • New: when the app can import dox_mailer, jobs.g.dart also lists the mail jobs of Mail.queue() (SendQueuedMail and SendEncryptedQueuedMail). So the worker can read them before Mail.configure() runs. The saved job names do not change. A dox_mailer without these classes (3.1) gets no mail lines.
    • Finds DoxProvider classes from dox_annotation. Release it together with dox_annotation and dox_core. An app must upgrade dox_builder together with dox_core, or its providers are not found.
    • New: the OpenAPI schema of a model reads visibleFields, like hidden: with a list, only its keys are in the schema. Needs the next dox_orm for toJson() to match.
    • New: onTrashed() counts as a model hook, so a model with only that hook gets hasModelHooks. Needs the next dox_orm.
    • New: models get $copyColumnsFrom(). It copies every column field from another model of the same class. refresh() in the next dox_orm uses it, so it works for columns with a cast or a beforeGet. Nothing else calls it, so reads and saves do no extra work.
    • New: models read @HasManyThrough and @HasOneThrough. Needs the next dox_orm.
    • New: DTOs read @Dto(trim: true), @Dto(coerce: true) and @Dto(attributes: {...}). Needs the next dox_validation.
    • New: @After and @Before take 'today', 'tomorrow', 'yesterday' and the input key of another DateTime field. New @AfterOrEqual and @BeforeOrEqual. A text that is not a date, a word or a DateTime field stops the build. The words and fields work with any dox_validation. @AfterOrEqual and @BeforeOrEqual need the next dox_validation.
    • New: DTOs read @RequiredUnless, @RequiredWithout, @RequiredWithoutAll, @Filled, @Present, @Prohibited, @ProhibitedIf, @ExcludeIf and @ExcludeUnless. Each one on an always-required field stops the build, like @RequiredIf. Needs the next dox_validation.
    • New: the rules @Different and the field compare rules check the whole field on a List field, not each item. Rules that name another key stop the build when they name a Dart field name in place of the input key.
    • A DTO that uses none of these gets the same code as before.
    • OpenAPI: a controller method that calls req.authorize(...) gets a 401 and a 403 answer in the docs. A @Response with the same status wins.
    • OpenAPI: a controller method that calls req.validateSchema(...), or req.validate<T>() with no request class found, gets a 422 answer. A @Response(422, ...) wins. Needs the next dox_core.
    • OpenAPI: a controller method that calls Gate.authorize(...) gets a 403 answer in the docs. A @Response(403, ...) wins.
    • DTOs: a DTO with no @RequiredIf or @RequiredWith field (and no nested DTO with one) now writes usesRequiredWhen => false. Then the check does not keep each converted value, which saves work. Needs the next dox_validation.
    • New: DTO code reads the DTO flags of ValidationFlags at run time: dtoAllErrors, dtoRejectEmptyList and dtoMaybeRejectsEmpty. All are off by default, so the checks work as before. The builder writes this code only when the app's dox_validation has DtoState.allErrors. With an older dox_validation it writes the old code, so it still compiles.
    • New: a model @BelongsTo field passes its name as relation: to belongsTo(), for the dox_orm flag belongsToKeyFromRelation. The builder writes it only when the app's dox_orm has the relation: parameter. With an older dox_orm the code does not change.
    • Fix: @OrDefault() on a Maybe<T> field no longer stops the build. A bad value gives Maybe.missing().
    • Fix: a nested DTO deeper in lists and maps, like List<List<A>> or Map<String, List<A>>, now runs its validate() and its async rules. Before, only one level (List<A>, Map<String, A>) was found. So after build_runner, an app may now get errors from these deeper DTOs that were skipped before.

    3.1.3

    • Version bump only, to match the other packages.

    3.1.2

    • DTOs: @Describe('...') on a field sets description in its JSON Schema (the generated toJsonSchema() and the OpenAPI docs). It wins over the /// doc comment. Needs dox_validation 3.1.2.

    3.1.1

    • DTOs: @Dto(emptyStringsToNull: true) makes the generated code read "" as null (needs the next dox_validation).
    • DTOs: @OrDefault() makes a bad value of that field give its default (or null) instead of an error. A field with @OrDefault() and no default that is not nullable stops the build.

    3.1.0

    • Fix: the JSON Schema pattern of @AlphaDash now allows digits, like the check does (needs dox_validation 3.1.0). The OpenAPI output of a DTO with @AlphaDash changes.
    • Fix: in generated DTO code, @RequiredIf and @RequiredWith now run after all fields are converted. Before, a rule on a field read the raw value of a field that comes after it, like ' PRO ', not 'pro' after @Trim and @Lowercase. Run build_runner to get the new code.
    • Fix: reload() and preload now set a nullable @HasOne, @BelongsTo, @MorphOne or @MorphTo field to null when the related row is gone. Before, the field kept its old value. Run build_runner to get the new code.
    • Fix: reload() and preload now set a @HasMany, @ManyToMany or @MorphMany field to an empty list when there are no related rows. Before, the field kept its old list. Run build_runner to get the new code.
    • Behavior change: a nullable list relation, like List<Tag>? tags, is now [] (not null) after a preload with no rows.
    • DTOs: @RequiredIf('type', 'company') and @RequiredWith(['phone']) from dox_validation. The field is required only when the condition is true. Use them on a nullable field, a Maybe field or a field with a default. On an always-required field the build stops with a clear error.
    • DTOs: the build stops when @RequiredIf, @RequiredWith, @Same or @Confirmed(other:) names a Dart field (like accountType) instead of its input key (account_type). The check would never match. It also stops for a @DateFormatted format with a letter it does not know.
    • DTOs: in a @Dto(strict: true) class, the key that @Confirmed reads (like password_confirmation) is not an unknown key.
    • New: DTO file rules @MinSize('10KB'), @MimeTypes(['image/png', 'image/*']) and @Dimensions(minWidth:, maxWidth:, minHeight:, maxHeight:, width:, height:, ratio:). They need dox_validation 3.1.0 or newer. A bad size or a @Dimensions() with no limit stops the build.
    • New: @ManyToMany(withPivot: [...], withTimestamps: true) is passed to the ORM, so the relation reads the extra pivot columns. Needs dox_orm 3.1.0 or newer.
    • New: the model builder makes the code for @MorphMany, @MorphOne and @MorphTo (polymorphic relations). A @MorphTo field has no model: its type is the field type, like Model<dynamic>, and its morph name is the field name in snake_case. The OpenAPI model schema has these relation keys too. Needs dox_orm 3.1.0 or newer.

    3.0.2

    • Breaking: column and JSON keys can change. Please read this before you update.
    • Digits are no longer split off. Before, address2 gave the key address_2. Now it gives address2.
    • A name you give is used exactly as written. Before, @Column(name: 'userID') gave user_i_d. Now it gives userID. The same is true for @Computed(name:), and for primaryKey, createdAt and updatedAt in @DoxModel.
    • DTO input keys change the same way: a field line2 now reads the key line2, not line_2.
    • What to do: run build_runner and look for changed keys in the generated files. Then rename the column in a migration. Or keep the old key with @Column(name: 'address_2') (or @Name('line_2') on a DTO field).
    • Fix: types from an import with a prefix (import 'other.dart' as o;) keep the prefix in the generated code, like o.Role, List<o.Role>, EnumCast(o.Role.values) and o.$InnerDto. Before, the code did not compile. This works in models, DTOs, env classes and scopes.
    • Fix: @Column(cast: ...) now works for a model in a part file. The cast is read from the AST of the field.
    • Fix: table names, column keys and relation keys are escaped in the generated code (\, ' and $).
    • Fix: a private class (like _AdminRouter or @Inject() class _Cache) is no longer put in container.g.dart, where it did not compile. The build shows a warning with the class and file.
    • Fix: container errors now show the file and line of the problem.
    • New: a constructor parameter of an abstract type gets the one container class that implements it. When two or more classes implement it, the build stops and names them.

    • Breaking: dox_websocket is gone. Use dox_socketio for realtime. Dox().websocket and Dox().setWebsocket() are removed.
    • Breaking: Route.websocket(path, handler) is now a raw WebSocket route. handler gets the open WebSocket and the DoxRequest. Middleware runs first. A request that is not a WebSocket upgrade gets 400.
    • dox_http_native now lives in its own repo (dartondox/dox-http-native). Dox uses it from pub.dev (^3.0.0-alpha.7). Its build hook downloads a ready-built library, so you do not need Rust.
    • Perf: faster route matching. A plain route is found with one map lookup, also when a param route was added before it (as long as that param route can not match the same path). Param routes are grouped by their first path segment, so a request only tries the routes that can match. The first matching route still wins.
    • Perf: the request handler reads Host and Content-Type once per request. Host is read only when the app has a Route.domain() route. HttpBody.read() takes an optional contentType.
    • Perf: on the native server, a JSON or form body is used as it is, with no stream in between. The size limit is still checked.
    • Perf: JSON responses are encoded in 8 KB chunks, not 256 bytes.
    • Perf: fewer objects per request. RouteData.params, DoxRequest.param and DoxRequest.method are made on first use. RouteData.domainLower is made once. CORS header lists are joined once.
    • Perf: one Future less per async request (then(onError:) instead of then().onError()).
    • Perf: multipart parsing makes its regexes once, and no longer builds a Future.any per chunk.
    • Perf: LogMiddleware lowercases the redact words once, not per key.
    • Perf: an error response reads APP_ENV and lowercases it only when the value changed.
    • Perf: IocContainer calls T.toString() once per call.
    • Breaking: the dart:io server is gone. Every app runs on the native server (dox_http_native), also an app with WebSocket or Socket.IO routes. AppConfig.server, the ServerBackend enum and the DOX_SERVER env var are removed. DoxServer.usesNative() and the isolateId option of DoxServer.listen() are removed.
    • Breaking: when the native library does not load, Dox stops at start with an error. It says why (eg. an ABI mismatch) and how to fix it (install Rust so the build hook can build it, or rebuild your lib_path library). Before, Dox logged a warning and used dart:io.
    • On a graceful stop (SIGTERM, Dox().stop()), open WebSockets get close code 1001.
    • Perf: AESEncryptor keeps the key bytes of the last secret and writes the output into one buffer. Decode reads the nonce and text without copies. The output format is the same.
    • New: Hash.makeAsync() and Hash.verifyAsync(). They run bcrypt in another isolate, so a request does not block the server.
    • New: Hash.rounds (default 10) sets the bcrypt cost. Hash.make() also takes rounds:.
    • Security: the app does not start when APP_KEY is empty, not exactly 32 characters, or one of the old public sample keys from .env.example. With such a key anyone can sign tokens and cookies. In APP_ENV development, local or test Dox only logs a warning. A longer key (eg. 48 or 64 characters) is refused too, because AES needs a key of 16, 24 or 32 bytes and every encrypted cookie failed with it. Before, only an empty key in production stopped the app. Run dox key:generate for a new key.
    • Security: a multipart part header with many backslashes (name="\\\\...) no longer blocks a server isolate for hours (ReDoS in the quoted string regex).
    • Security: a StreamFile response (Storage().stream(), Route.files()) with an html, xml, svg or javascript type is sent with Content-Disposition: attachment and Content-Security-Policy: sandbox. Every StreamFile gets X-Content-Type-Options: nosniff. Before, an uploaded x.html or x.svg was shown inline, and its script ran on the app origin (stored XSS).
    • Security: a Route.domain() route only matches when the Host header matches. Before, a request with no Host matched every domain route. A Host with a port (admin.app.com:8080) now matches Route.domain('admin.app.com').
    • Security: an encrypted cookie is bound to its name (AES-GCM associated data). A value made for locale gives null when it is sent as user_id. AESEncryptor.encode()/decode() take a new associatedData option. Encrypted cookies made by older versions no longer decrypt, so req.cookie() gives null for them once. Users may need to log in again.
    • Security: DoxCookie is HttpOnly by default. secure is null by default, which sets Secure when the request came over https (req.scheme(), see trustedProxies). Set httpOnly: false or secure: false to change it.
    • Security: the native server checks maxBodySize and maxMultipartSize on their own. Before, Rust let any body up to the bigger limit (100 MB) through, so a JSON body could take 100 MB of RAM before Dart said 413.
    • New AppConfig.bodyTimeout (default 120 seconds). On the native server, a client that does not send the whole body in this time gets 408. It stops slow clients that hold memory and connections.

    3.0.0-alpha.6

    • Security: Storage().putRequestFile() and RequestFile.store() no longer trust the client file name when the bytes are a known format that does not match it. Before, a valid png sent as a.html passed @Image/@Mimes and was saved as .html, so Route.files() served it as text/html on the app origin (stored XSS). Now it is saved with the extension of the bytes (.png).
    • Security: new upload file names use a random uuid (v4), not a time-based one (v1). A v1 name shows the upload time and the server, and the next name is easy to guess.
    • Security: trustedProxies: ['*'] trusts the direct peer only. req.ip() is the right-most X-Forwarded-For hop, the one the proxy added. Before, * also trusted every hop in the header, so req.ip() was the left-most value, which the client sets (X-Forwarded-For: 6.6.6.6). That broke IP rate limits and allow lists, also behind the Fly.io proxy of the deploy guide.
    • Security: LogMiddleware writes [REDACTED] for body fields and headers whose name has password, passwd, secret, token, authorization, cookie, api_key, api-key or apikey in it (upper or lower case). Before, the login body (with the password) and, with withHeader: true, the Authorization header went to the log as plain text. Change the list with LogMiddleware(redact: [...]).
    • Security: an error that is not an IHttpException answers 500 with {"code": "server_error", "message": "Server Error"}. The error text is sent only when APP_ENV is development or local. Before, the client always got error.toString(), which can hold SQL, table names, file paths or database hosts. errorHandler still gets the full error.
    • Graceful shutdown closes the cache stores of Cache() (eg. Redis), in every isolate, after the DoxShutdown services. Your app needs no extra code.
    • The ORMService of a new project implements DoxShutdown and calls SqlQueryBuilder.close(), so the database connections close on shutdown too. In an older project, add this to lib/services/orm_service.dart: 
      class ORMService implements DoxService, DoxShutdown {
  // setup() as before

  @override
  Future<void> shutdown() async {
    await SqlQueryBuilder.close();
  }
