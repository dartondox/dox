    Coming from Laravel

    This page is for Laravel developers: it shows the Laravel way and the Dox way side by side.

    The Laravel code is Laravel 11. The biggest changes are in What is different.

    Routing

    Laravel Dox
    Route::get('/ping', fn () => 'pong'); Route.get('/ping', (DoxRequest req) => 'pong');
    Route::post('/blogs', [BlogController::class, 'store']); Route.post('/blogs', blogController.store);
    Route::get('/blogs/{id}', ...) and function show(int $id) Route.get('/blogs/{id}', ...) and show(int id)
    Route::get('/posts/{page?}', ...) Route.get('/posts/{page?}', (int? page) => ...)
    ->where('path', '.*') Route.get('/docs/{page*}', (String page) => ...)
    Route::prefix('blogs')->group(function () { ... }); Route.group('/blogs', () { ... });
    Route::middleware('auth')->group(...) Route.middleware(<dynamic>[AuthMiddleware()], () { ... });
    Route::domain('admin.app.test')->group(...) Route.domain('admin.app.test', () { ... });
    Route::resource('blogs', BlogController::class); Route.resource('blogs', BlogController());
    routes/api.php with the api prefix lib/routes/api.dart, a Router class with prefix => 'api'

    In Dox, a controller is an object you make yourself. There is no BlogController::class string.

    lib/routes/api.dart
    class ApiRouter extends Router {
  @override
  String get prefix => 'api';

  @override
  List<dynamic> get middleware => <dynamic>[];

  @override
  void register() {
    BlogController blogController = BlogController();
    Route.get('/blogs', blogController.index);
    Route.resource('users', UserController());
  }
}

    Controllers

    Laravel Dox
    php artisan make:controller BlogController dox create:controller Blog
    php artisan make:controller BlogController --resource dox create:controller Blog -r
    public function show(Request $request, int $id) Future<Blog?> show(DoxRequest req, int id)
    public function store(StoreBlogRequest $request) Future<Blog> store(CreateBlog body)
    injected by the service container filled by type: DoxRequest, one @Dto class, path params

    Dox fills a parameter by its type, not by its name. Path params go by position. A controller can be a class method, a static method or a plain function.

    Middleware

    Laravel Dox
    php artisan make:middleware Logger dox create:middleware Logger
    public function handle(Request $request, Closure $next) dynamic handle(IDoxRequest req)
    return $next($request); return req;
    return response('no', 401); return response('no').statusCode(401);
    abort(404); throw NotFoundHttpException();
    $middleware->append(LogMiddleware::class) in bootstrap/app.php AppConfig(globalMiddleware: <dynamic>[LogMiddleware()])
    lib/app/http/middleware/logger.middleware.dart
    class LoggerMiddleware implements IDoxMiddleware {
  @override
  dynamic handle(IDoxRequest req) {
    print('${req.method} ${req.uri.path}');
    return req; // go on. anything else is the response.
  }
}

    A plain function dynamic apiKey(DoxRequest req) also works as middleware. Dox middleware runs before the controller only. There is no "after" step; use a responseHandler for that.

  @Column()

    Every column field is nullable, because a new model has no values yet. Dox has no global scopes and no $casts list. Use the field type, beforeSave and beforeGet. See Model.

    Dart can not load files at run time in an AOT binary. So the CLI keeps a list of your migrations in db/migration/migrations.dart. You do not edit it. The server can run the migrations at start. See Migration.

    Artisan vs the dox CLI

    Laravel Dox
    laravel new blog dox create blog
    php artisan serve dox serve (or dox s), with hot restart and build_runner watch
    php artisan make:resource dox create:serializer
    php artisan key:generate dox key:generate
    php artisan route:list not there. Use the OpenAPI docs page at /docs.
    php artisan tinker not there
    php artisan optimize dox build (one native binary in build/bundle)

    The make:* and migrate commands are in the tables above. Two commands have no Laravel twin: dox build_runner:build makes the generated code, and dox env:generate makes the typed env class. See Dox CLI.

    Dox auth is a JWT in the Authorization header. There are no sessions, no cookies and no Sanctum tokens table. See Authentication.

    Config and .env

    Laravel Dox
    config/*.php files lib/config/*.dart files, put together in AppConfig
    env('APP_KEY') env.appKey (a getter in lib/config/env.dart)
    env('APP_PORT', 3000) env.appPort (the default is in the getter: int get appPort => 3000;)

    What is different

    • No service container in the controller. Laravel makes your controllers and injects what the constructor asks for. In Dox you make the controller yourself (BlogController()) and pass what it needs. Dox fills only the method parameters: the request, one DTO and the path params. Dox().ioc is a small registry (register, registerSingleton, get), but nothing is injected for you.
    • Isolates, not PHP-FPM workers. One process runs one isolate per CPU core. Each isolate runs your whole app and has its own memory. A static value or a singleton lives once per isolate. A PHP worker starts from zero on each request. A Dox isolate keeps its state between requests, so a memory leak stays. Anything that must be shared goes to the database, Redis or files. See How Dox works.
    • Code generation, not reflection. Laravel reads your classes at run time. Dart has no usable reflection in a compiled app. So build_runner with dox_builder writes the model code, the DTO checks, the env class and the OpenAPI docs into .g.dart files. Run dox build_runner:build after a change, or let dox serve watch for you.
    • One native binary. dox build makes an AOT binary in build/bundle. There is no interpreter, no vendor/ folder and no composer install on the server. The Docker image is about 11 MB.
    • A native HTTP server and native database drivers. Rust parses HTTP and talks to Postgres and MySQL. Your code stays in Dart. They come ready-built, so you do not need Rust.
    • Types everywhere. A DTO is a class with typed fields. A path param is an int. A model field is a String?. The compiler finds many mistakes before you run the app.
    • Async is explicit. Database calls return a Future. You write await. One isolate serves many requests at the same time while it waits for the database.
    • JSON API first. Dox returns text, JSON, files and streams. It has no view layer.

    What is missing today

    Dox does not have these Laravel features yet:

    • queues and jobs, and the task scheduler
    • events and listeners (model events are there)
    • Blade views, mail and notifications
    • sessions (auth uses a JWT; encrypted cookies are there)
    • policies and gates
    • seeders and factories
    • rate limiting middleware
    • savepoints in nested transactions (a nested transaction() joins the outer one)

    See What Dox does not have yet for what to use today.

    What is there, as separate packages: validation, OpenAPI docs, storage, cache, Socket.IO and auth.
